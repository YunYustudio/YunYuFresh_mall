# 运维部署技术文档 · 生鲜商城小程序

> 面向运维 / 部署人员。描述「生鲜商城小程序」全栈三端（后端 `Mall_YunYu` / PC 后台 `soybean-admin` / 微信小程序 `uni_free_mall`）的环境依赖、初始化、打包、运行、反向代理与常见问题。
> 本文为**随仓库发布的自洽版**：所有路径均指向本项目内真实存在的文件（重点是 `12_运维部署/全量数据库fresh_mall.sql`），不再依赖仓库外文档。
> 最后更新：2026-08-20

## 一、系统组成总览

| 工程 | 角色 | 技术栈 | 产物 | 默认端口 |
|------|------|--------|------|---------|
| `Mall_YunYu` | 后端 API 服务（小程序 + 后台共用） | Spring Boot 3.3.4 / JDK 21 / MyBatis-Plus 3.5.7 / Sa-Token / Redis / MySQL | 可执行 jar（`java -jar` 直接跑） | **8080**（无 context-path） |
| `soybean-admin` | PC 运营管理后台 | Vue3 + Vite + Naive UI + pnpm 单仓（workspace） | 静态 `dist/` | 纯静态，由 Nginx 托管 |
| `uni_free_mall` | 微信小程序（C 端） | uni-app（Vue3 + TS + Pinia） | 微信小程序代码包（HBuilderX 发行 / CLI 构建） | 小程序运行时在微信侧 |

依赖中间件：**MySQL 8.x**（业务库，库名建议 `fresh_mall`）、**Redis**（分布式锁 / Sa-Token 会话，默认无密码 db0）。

## 三、数据库初始化（关键）

本仓库已内置一份**完整数据库导出**：`12_运维部署/全量数据库fresh_mall.sql`。它由运行中的生产库（库名 `fresh_mall`）整库导出，包含：

- **全部业务表结构**（31 张表，`id` 均为 `BIGINT UNSIGNED NOT NULL AUTO_INCREMENT`），并且已含最新字段（如 `order_info.source_cart_ids`、`order_info.version` 乐观锁等），**全新部署无需再跑任何迁移/修复脚本**。
- **演示数据**：商品（SPU / SKU / 库存）、分类、轮播 Banner、公告、店铺配置等，开箱即有内容可演示。

### 3.1 全新部署（推荐）

```bash
# 建库并导入
mysql -uroot -p -e "CREATE DATABASE IF NOT EXISTS fresh_mall DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;"
mysql -uroot -p fresh_mall < "12_运维部署/全量数据库fresh_mall.sql"
```

> ⚠️ 若用 Navicat 等工具导入：先新建 `fresh_mall` 库并选中，再「运行 SQL 文件」导入。该 SQL 已使用 `SET NAMES utf8mb4`，无需额外设置。

### 3.2 关于旧库升级

历史库曾出现「活库表结构漂移导致 INSERT 报 `Field 'id' doesn't have a default value`」等迁移问题，对应的一批修复/迁移脚本位于原开发文档（`11_数据库修复脚本/`、`09_系统配置/`、`04_支付与交易/`）下，**未随本仓库发布**。全新部署直接用 3.1 的整库 SQL 即可；若确有**旧库原地升级**需求，请通过 README 底部联系方式索取对应迁移脚本。

### 3.3 系统配置

支付等关键参数以 `sys_config` 表为准（后台「系统配置」页维护）；`application*.yml` 仅作兜底占位。首次部署使用演示模式（`sys_config.wxpay_enabled=0` + `pay_demo_enabled=1`）即可跑通下单→支付→回调全流程，无需真实商户号。

## 四、后端 `Mall_YunYu` 部署

### 4.1 打包

```bash
cd Mall_YunYu
mvn clean package -DskipTests
# 产物: target/Mall_YunYu-0.0.1-SNAPSHOT.jar
```

### 4.2 运行

```bash
# 开发 / 演示用 dev profile（默认）
java -jar Mall_YunYu-0.0.1-SNAPSHOT.jar

# 生产用 prod profile（关闭 SQL 日志、关闭 Knife4j、强制 useSSL）
java -jar Mall_YunYu-0.0.1-SNAPSHOT.jar --spring.profiles.active=prod
```

### 4.3 生产环境变量清单（务必通过环境变量注入，禁止写死到提交的 yml）

| 变量 | 必配 | 说明 |
|------|------|------|
| `SPRING_PROFILES_ACTIVE` | ✅ | 生产设 `prod`；不设为 `dev` |
| `MYSQL_URL` | ✅ | `jdbc:mysql://<host>:3306/fresh_mall?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=true&requireSSL=true&verifyServerCertificate=true` |
| `MYSQL_USERNAME` / `MYSQL_PASSWORD` | ✅ | 数据库账号密码 |
| `REDIS_HOST` / `REDIS_PORT` / `REDIS_DB` | 按需 | 默认 `localhost:6379` / db0；非本机必配 |
| `MALL_CONFIG_SECRET` | ⚠️ **必改** | `sys_config` 中 APIv3Key / COS SecretKey 的 AES 加密种子。**用默认值等于没加密**，拖库即泄露；改后需在后台重新填写已加密密钥 |
| `MALL_CERT_PATH` | 真收款时 | 微信支付证书目录，prod 默认 `/data/mall/certs`。**严禁**放在 `MALL_UPLOAD_PATH` 下或映射为静态资源，否则商户私钥可被公网下载；权限建议 `chmod 600` |
| `MALL_UPLOAD_PATH` | ✅ 容器部署 | 本地上传根目录，prod 默认 `/data/mall/uploads`。**务必挂载持久化卷**，否则重新发版图片全丢 |
| `MALL_UPLOAD_DOMAIN` | ✅ 生产 | 图片外链域名（如 `https://api.your-domain.com`）。留空会自动取请求域名，但库里可能存成内网地址，**生产必设** |
| `WX_MINIAPP_APPID` / `WX_MINIAPP_SECRET` | ✅ | 小程序 appid / secret（个人主体体验版也需，用于 `wx.login` 换 session） |
| `WX_PAY_*`（`WX_PAY_APPID` / `WX_PAY_MCH_ID` / `WX_PAY_API_V3_KEY` / `WX_PAY_CERT_SERIAL_NO` / `WX_PAY_PRIVATE_KEY_PATH` / `WX_PAY_PRIVATE_CERT_PATH` / `WX_PAY_NOTIFY_URL` / `WX_PAY_REFUND_NOTIFY_URL`） | 真收款时 | 微信支付 V3 参数，权威来源是 `sys_config` 表（后台「系统配置」维护），此处仅在 `sys_config` 未建/未填时兜底 |

> 兜底值见 `Mall_YunYu/src/main/resources/application.yml` / `application-prod.yml`。yml 里只放 `${...:}` 占位，**真实密钥不入库文件、不提交代码仓库**（项目红线）。部署时用 `export` 或 systemd 环境段注入。

### 4.4 进程守护（任选其一）

```bash
# 最简：nohup
nohup java -jar Mall_YunYu-0.0.1-SNAPSHOT.jar --spring.profiles.active=prod \
  > /data/mall/logs/mall.log 2>&1 &

# 推荐：systemd（/etc/systemd/system/mall-yunyu.service）
# [Unit] Description=Mall_YunYu After=network.target
# [Service] User=mall WorkingDirectory=/data/mall ExecStart=/usr/bin/java -jar /data/mall/Mall_YunYu-0.0.1-SNAPSHOT.jar --spring.profiles.active=prod
# [Install] WantedBy=multi-user.target
# → systemctl enable --now mall-yunyu
```

### 4.5 接口文档

- 开发（dev）：Knife4j 在 `http://<host>:8080/doc.html` 自动开启。
- 生产（prod）：`knife4j.enable=false` + `production=true`，**对外关闭**，避免暴露接口清单。
- 另可用仓库内脚本 `Mall_YunYu/gen_api_doc.py`（先启动后端再运行）一键导出完整接口清单。

## 五、PC 后台 `soybean-admin` 部署

```bash
cd soybean-admin
pnpm install          # workspace 单仓，必须用 pnpm（engines 要求 pnpm>=10.5）
pnpm build            # = vite build --mode prod，产物在 dist/
```

1. **构建前改 API 地址**：后端地址由 `.env.prod` 中的 `VITE_SERVICE_BASE_URL` 决定。该文件为 git 忽略项、仓库内**可能未包含**——若缺失请自行在 `soybean-admin/` 下创建 `.env.prod`，内容参考：

   ```
   # 生产环境后端地址（换成你的后端域名/IP，不含末尾斜杠）
   VITE_SERVICE_BASE_URL=https://api.your-domain.com
   ```

2. **部署**：把 `dist/` 整个目录交给 Nginx 托管（静态文件），并对 `/api` 做反向代理到后端 8080（见第七节）。
3. **客服二维码 / 上传**等走后端 `/api`，同源或跨域已由后端统一放开（本项目 `/api` 统一前缀 + CORS）。

## 六、微信小程序 `uni_free_mall` 部署

> ⚠️ **个人主体限制**：微信小程序若为**个人开发者主体、无营业执照**，则**真实微信支付 JSAPI 无法开通商户号**，生产支付链路跑不通。此时请使用后端的**模拟支付**开关（`sys_config.pay_demo_enabled=1`）体验「下单→支付→回调」全流程并于小程序真机预览演示。要真实收款须先办个体工商户/企业执照 + 升级主体 + 申请商户号，再按环境变量注入 `WX_PAY_*`。

### 方式 A（推荐）：HBuilderX 发行

1. 打开 `uni_free_mall` 工程。
2. 改 API 地址：后端地址由 `.env.production` 中的 `VITE_API_BASE_URL` 决定。该文件为 git 忽略项、仓库内**可能未包含**——若缺失请自行在 `uni_free_mall/` 下创建 `.env.production`，内容参考：

   ```
   # 客户手机/体验版可达的后端地址，含协议、不含末尾斜杠
   VITE_API_BASE_URL=https://api.your-domain.com
   ```

   > 不填或留占位 → 小程序里图片和接口都指向 `localhost:8080`，真机/体验版全部失败。
3. 顶部菜单「发行 → 小程序-微信」，生成 `unpackage/dist/build/mp-weixin`。
4. 微信开发者工具导入该目录 → 上传 → 设为体验版 / 提交审核发布。

### 方式 B：CLI 构建

```bash
cd uni_free_mall
npm install
npm run build:mp-weixin     # 产物在 dist/build/mp-weixin
# 再用微信开发者工具导入构建产物
```

### 注意

- `getPhoneNumber`（手机号快捷获取）个人主体不支持，只能让用户手动填表单。
- 隐私保护指引在微信公众平台「服务内容声明」填写并审核，小程序内用 `wx.openPrivacyContract()` 拉起官方页，**不要自建协议页**。
- 体验版免过类目 / 微信支付审核；正式发布需按需补齐类目。
- 支付主链路（回调验签 → 幂等 → 对账补偿）实现说明见仓库 `README.md` 第 4 节「功能实现详解」。

## 七、反向代理（Nginx 参考）

```nginx
server {
  listen 443 ssl;
  server_name your-domain.com;   # 换成你的域名，并配置 ssl_certificate / ssl_certificate_key

  # 后端 API
  location /api/ {
      proxy_pass http://127.0.0.1:8080/;
      proxy_set_header Host $host;
      proxy_set_header X-Real-IP $remote_addr;
      proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  }

  # 本地上传图片（MALL_UPLOAD_PATH 映射，上传目录须持久化）
  location /uploads/ {
      alias /data/mall/uploads/;
      expires 7d;
  }

  # PC 后台静态资源（root 指向 soybean-admin/dist）
  location /admin/ {
      alias /data/www/admin/dist/;
      try_files $uri $uri/ /admin/index.html;
  }
}
```

> 证书目录 `MALL_CERT_PATH` **绝对不要**做 `location` 映射，避免 `apiclient_key.pem` 被公网下载。

## 八、常见问题（排障）

| 现象 | 原因 | 处理 |
|------|------|------|
| 加购物车 / 收藏 / 下单等 INSERT 报 `Field 'id' doesn't have a default value` | 表 `id` 丢失 `AUTO_INCREMENT`（多为旧库迁移遗留） | 全新库用「三、3.1」整库 SQL 不会出现；旧库请走原开发文档修复脚本，或重建受影响表后重导整库 SQL |
| 小程序真机 / 体验版图片、接口全部失败 | `.env.production` 的 `VITE_API_BASE_URL` 是 localhost 或占位 | 改成客户可达地址后**重新发行**小程序 |
| 后台页面接口 404 / 跨域 | `VITE_SERVICE_BASE_URL` 不对，或 Nginx 未反代 `/api` | 核对后台 `.env.prod` 并重新 `pnpm build` |
| 微信登录报 `登录失败请重试`（WX_LOGIN_ERROR） | 未注入 `WX_MINIAPP_APPID/SECRET` 或值错 | 注入正确环境变量后重启后端 |
| 退款报「可用余额资金不足」 | 微信商户可用余额不足 | 商户平台充值后重试 |
| 上传图片后重新发版丢失 | `MALL_UPLOAD_PATH` 没挂持久化卷 | 容器 / 部署目录挂载持久卷到 `/data/mall/uploads` |
| 库里图片 URL 是内网地址 | `MALL_UPLOAD_DOMAIN` 未设 | 生产设对外域名，历史脏数据后台重传 |

## 九、备份与回滚建议

- **数据库**：定期 `mysqldump fresh_mall`（含 `sys_config` 已加密密钥；`MALL_CONFIG_SECRET` 必须同环境保留，否则密文不可解密）。
- **上传文件**：`/data/mall/uploads` 随服务器快照 / 对象存储同步。
- **证书**：`/data/mall/certs` 单独备份且权限收紧。
- **回滚**：后端 jar 保留上一版本，停服替换即可；前端静态 `dist/` 保留上一版目录做软链切换。
- **演示数据清理**：演示模式产生的订单/用户等演示数据，建议按需定向删除（不要 `TRUNCATE` 业务表），避免残留脏脚本影响真实运营。
